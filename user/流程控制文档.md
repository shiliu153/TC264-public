## 1. 系统启动流程

### 1.1 硬件复位入口

复位后，硬件自动跳转到地址 `0x80000020`，执行 `_START()`。

```
复位向量
  │
  └── _START()                         [IfxCpu_CStart0.c:210]
        └── __non_return_call(_Core0_start)  [IfxCpu_CStart0.c:212]
```

### 1.2 CPU0 启动序列 (`_Core0_start`)

`_Core0_start()` 位于 `libraries/infineon_libraries/iLLD/TC26B/Tricore/Cpu/CStart/IfxCpu_CStart0.c:107`，按以下顺序执行：

### 1.5 CPU1 用户初始化序列 (`core1_main`)

`core1_main()` 位于 `user/cpu1_main.c:65`：

| 调用函数 | 行号 | 说明 |
|---------|------|------|
| `disable_Watchdog()` | 67 | 禁用CPU1看门狗 |
| `interrupt_global_enable(0)` | 68 | 使能全局中断 |
| `cpu_wait_event_ready()` | 74 | 等待CPU0初始化完成 |

初始化完成后，CPU1进入 `while(TRUE) {}` 空循环 —— 所有实际工作在 **10kHz FOC ISR** 中完成。

### 1.6 双核同步机制

```
时间线：
────────────────────────────────────────────────────────────────────►
CPU0: _START → _Core0_start → 启动CPU1 → core0_main(全部初始化) → cpu_wait_event_ready()
CPU1:                                    _Core1_start → core1_main(最小初始化) → cpu_wait_event_ready()阻塞...
                                                                                  ...解除 → 空循环+ISR
```

- CPU0 调用 `cpu_wait_event_ready()` 在全部初始化完成后 (cpu0_main.c:223)
- CPU1 调用 `cpu_wait_event_ready()` 仅做最小初始化后 (cpu1_main.c:74)
- 双核在此处同步，确保 CPU0 的所有外设、传感器、定时器就绪后 CPU1 才进入工作状态

### 2.2 优先级排序

```
优先级数值(越大越高):

255 ─ exti_ch0_ch4_isr (EXIT CH0/4)
254 ─ exti_ch3_ch7_isr (EXIT CH3/7)
200 ─ cc61_pit_ch0_isr (FOC 10kHz, CPU1)  ← 最高优先级用户ISR
 33 ─ cc61_pit_ch1_isr (控制1kHz)
 31 ─ cc60_pit_ch1_isr (巡线200Hz)
 30 ─ cc60_pit_ch0_isr (IMU 200Hz)
 21 ─ uart3_er_isr
 20 ─ uart3_rx_isr
 17 ─ uart2_rx_isr (WiFi模块)
 10 ─ uart0_rx_isr (调试串口)
  7 ─ exti_ch1_ch5_isr (摄像头PCLK, DMA)
  6 ─ exti_ch2_ch6_isr (摄像头PCLK, DMA)
  0 ─ dma_ch6/7_isr (DMA完成)
```

### 2.3 中断嵌套策略

所有 ISR 在处理开始时调用 `interrupt_global_enable(0)` **使能中断嵌套**，允许更高优先级中断抢占。

**调用位置汇总**：
- `isr.c:174` — `cc60_pit_ch1_isr` (巡线)
- `isr.c:188` — `cc60_pit_ch0_isr` (IMU)
- `isr.c:339` — `foc_ctrl_periodic_isr` (FOC)
- `isr.c:737` — `cc61_pit_ch1_isr` (控制)
- `cpu1_main.c:68` — `core1_main` 入口

> **嵌套规则**：在 CPU0 上，巡线ISR(31)可被控制ISR(33)抢占，但不会被FOC ISR抢占(CPU不同)。在 CPU1 上，FOC ISR(200)没有更高优先级的用户中断可抢占它。

### 2.4 ISR 代码段放置

| 文件 | 行号 | 代码段 | 说明 |
|------|------|--------|------|

### 3.3 主菜单页面 (`menu_show_main`)

### 3.4 起跑页面 (`menu_run_task`)

**流程**：

```
  ├── 显示电池电压、百分比
  ├── 显示里程计左右轮计数
  ├── 显示当前路线索引
  ├── K4 按键检测 (menu.c:778)
  │   └── 切换 running 状态
  ├── 起跑检测 (menu.c:790-806)

  │   ├── 检查 line_follow_control_ready() → 重构标定
  │   └── 1秒倒计时 → g_run_enable = 1  (menu.c:806)
  ├── 停止检测 (menu.c:832-864)
  │   ├── g_run_enable = 0
  │   ├── bldc_drv8300_3pwm_motor_stop() ×2  (menu.c:858-859)
  │   ├── neg_pressure_motor_stop()           (menu.c:860)
```

### 4.3 运行时指令双缓冲协议

CPU0 的 1kHz ISR 发布速度指令 → CPU1 的 10kHz ISR 读取：

**发布端** (`foc_runtime_cmd_publish_isr`, isr.c:73)：
```
写入缓冲区 (非ready侧)
__dsync()           // 写内存屏障
更新 ready_index     // 原子切换缓冲区
__dsync()           // 写内存屏障
```

**读取端** (`foc_runtime_cmd_load`, isr.c:86)：
```
读取 ready_index
__dsync()           // 读内存屏障
从活跃缓冲区读取 run_enable, left_rpm, right_rpm
__dsync()           // 读内存屏障
```

用 **seq-lock** 协议保证 CPU0→CPU1 数据一致性，无锁设计。

### 4.4 角度换算链

```
原始ADC值 (14-bit, 0-16383)
  → foc_as5047p_raw_to_mech_rad()     → 机械弧度 [0, 2π)        [foc_svpwm.c:351]
  → foc_as5047p_raw_to_mech_fxp()     → 机械定标角 (12-bit)     [foc_svpwm.h:78]
  → foc_mech_fxp_to_elec_fxp()        → 电气定标角 (乘极对数)   [foc_svpwm.h:83]
  → 用于 foc_vdq_to_duty_fxp() 的 SVPWM 角度入参
```

### 4.5 速度估算细节

- **子采样率**：`FOC_SPEED_ESTIMATE_HZ = 1000Hz` (实际估算在1kHz周期)
- **估计算法**：`foc_speed_estimate_radps` (foc_svpwm.c:76) — 差分角度除以时间
- **平滑**：移动平均 (可配置样本数) + 一阶低通 (α = `g_as5047p_lp_alpha`)
- **死区**：|ω| < `g_as5047p_speed_zero_deadband_rpm` → 强制为0
- **方向修正**：用户定义的正方向可能与编码器方向不同，用 `foc_left/right_user_rpm_to_motor_rpm` 转换 (foc_svpwm.h:101,106)

### 6.3 控制就绪检查

`line_follow_control_ready()` — `line_follow.c:576`

返回 true 的条件：
1. 标定样本数 >= 阈值(每个通道有足够的 min/max 数据)
2. 灰度传感器接口正常

检查不通过时，delta=0，小车直行。

### 8.5 帧格式

`wifi_service_send_frame()` — `wifi_service.c:476`

```
[0] MAGIC0: 0xA5
[1] MAGIC1: 0x5A
[2] TYPE:   帧类型 (0x01/0x02/0x03/0x04)
[3] FLAGS:  标志字节
[4] LEN:    载荷长度
[5..N]:    PAYLOAD (N-4字节)
[N+1]:     CRC-8 (数据[2..N]的校验)
```

通过 `wifi_uart_send_buffer()` 经 UART2 发送给 WiFi 模块。

### 8.6 命令处理流程

`wifi_service_poll_command()` — `wifi_service.c:771`

从 UART2 RX 环形缓冲区读取数据 (256字节 `g_wifi_rx_stream`)，然后调用 `wifi_service_process_rx_stream()` (line 849) 进行帧/行分发：

**二进制帧处理** (magic 0xA5 0x5A)：
1. CRC-8 校验
2. 校验失败 → 搜索下一个同步字，必要时丢弃字节
3. 校验通过 → `wifi_service_handle_binary_frame()` (line 795)
   - 重复检测 (通过last seq/type)
   - `wifi_service_execute_control_opcode()` → START/PAUSE/ODOM_START/ODOM_CLEAR/NPON/NPOFF/SAVE

**ASCII 文本命令** (换行符终止)：

### 8.7 CRC-8 保护

- 多项式：0x07 (标准 CRC-8)
- 查表法实现：256 项预计算表 (wifi_service.c:649-682)
- 计算方法：`wifi_service_frame_checksum()` (wifi_service.c:684)
- 校验范围：TYPE ~ PAYLOAD_END (不包括 MAGIC 和 CRC 字节自身)

### 9.2 运行时指令双缓冲 (seq-lock)


**读取协议** (`foc_runtime_cmd_load`, isr.c:86)：
```
读 ready_index  →  __dsync() → 读活跃缓冲  →  __dsync()
```

### 9.3 WiFi 快照双缓冲

**生产者** (CPU0 1kHz ISR, `wifi_service_capture_snapshot_isr`)：
- 写入到 `g_wifi_snapshot_buffers[!ready_index]`
- 更新 `g_wifi_snapshot_ready_index` 和 `g_wifi_snapshot_ready`

**消费者** (CPU0 前台, `wifi_service_load_latest_snapshot`, wifi_service.c:748)：
- 关闭中断 (防止 ISR 中途修改)
- 检查 `g_wifi_snapshot_ready`
- 复制快照到本地栈变量
- 清除 `g_wifi_snapshot_ready`
- 恢复中断

### 9.4 内存分区

| 内存区域 | 用途 | 定义位置 |
|---------|------|---------|
| `cpu1_psram` | 所有 ISR 处理代码 + FOC 数学函数 | `isr.c:32`, `foc_svpwm.c:20` |
| `cpu1_dsram` | CPU1 主循环代码/数据 + DMA 链表 | `cpu1_main.c:49`, `zf_driver_dma.c:52` |
| `cpu0_dsram` | CPU0 代码和数据 | `cpu0_main.c:22` (pragma) |

> **设计理由**：ISR 代码和数据放在 CPU1 的 scratchpad RAM 中，利用 TC264 的紧密耦合内存 (TCM) 实现零等待访问，保证 10kHz FOC ISR 的实时性。`cpu1_dsram` 作为默认主机，大多数全局变量都在 CPU1 的数据 RAM 中。
