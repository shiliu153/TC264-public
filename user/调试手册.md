## 1. 调试基础设施

### 1.1 调试串口 (UART0)

- **外设**：UART0
- **初始化**：`debug_init()` → `user/cpu0_main.c:111`
- **中断接收**：`uart0_rx_isr()` → `isr.c:1081`，调用 `debug_interrupr_handler()`
- **配置宏**：`DEBUG_UART_USE_INTERRUPT` (条件编译，在 isr.c:1085)
- **用途**：printf 重定向输出，调试信息打印
- **波特率**：由 `debug_init()` 内部配置

### 1.2 ISR 时间分析 GPIO

用于示波器测量 ISR 执行时间的专用 GPIO：

- **引脚**：P02.6，初始化为 GPO，输出低电平 → `cpu0_main.c:217`
- **宏定义**：
  - `FOC_ISR_TIME_PROFILE_HIGH()` — 进入 FOC ISR 时拉高 → `isr.c:341`
  - `FOC_ISR_TIME_PROFILE_LOW()` — 退出 FOC ISR 时拉低 → `isr.c:714`
- **使用方法**：示波器探头接 P02.6，测量高电平脉宽 = FOC ISR 执行时间
- **期望值**：< 100μs (必须在下一个中断到来前完成)

### 1.3 WiFi 遥测系统

- **UART**：UART2 (P10.5/P10.6)
- **PC 上位机**：`user/pc_wifi_uart_plot_qt.py` — Python PyQt 实时绘图
- **连接方式**：小车 WiFi 模块连接路由器 → PC 连接同一网络 → TCP 192.168.137.1:9000
- **功能**：实时遥测数据可视化、远程命令发送、参数在线修改

### 1.4 显示屏 (IPS200)

- **接口**：SPI (P20.11/SCK, P20.12/MOSI, P20.13/CS, P20.14/DC, P20.15/RST, P15.4/BLK)
- **初始化**：`ips200_init(IPS200_TYPE_SPI)` → `cpu0_main.c:114`
- **显示区域**：160×128 像素
- **字高**：8 像素（每行 16 像素间距），最多显示约 8-10 行信息
- **用途**：离线调试（不需要 PC/WiFi 时的主要调试手段）

### 1.5 按键

- **初始化**：`keys_init()` → `cpu0_main.c:117`
- **按键定义**：K1=进入, K2=上, K3=下, K4=进入
- **读取函数**：`get_key_value()` — 阻塞轮询 + 去抖

### 1.6 电池监测

- **初始化**：`battery_monitor_init()` → `cpu0_main.c:134`
- **读取函数**：
  - `battery_monitor_get_voltage_v()` — 电池电压 (V)
  - `battery_monitor_get_raw()` — ADC 原始值
  - `battery_monitor_get_percent()` — 电量百分比
  - `battery_monitor_is_low()` — 低于低电阈值
  - `battery_monitor_is_critical()` — 低于严重低电阈值
- **全局变量**：
  - `g_battery_cells` (`battery_monitor.h:10`) — 电池串数
  - `g_battery_voltage_v` (内部静态) — 当前电压
- **保护逻辑**：
  - 低电：显示告警但仍可运行
  - 严重低电：`menu_run_task()` 拒绝起跑 (menu.c:790)

## 2. 菜单调试页面使用指南

### 2.1 页面概览

| 页面 | 编号 | 入口 | 用途 | 关键操作 |
|------|------|------|------|---------|
| MAIN | 0 | 开机默认 | 导航到各调试页 | K2/K3 选择，K4 进入 |
| RUN | 1 | MAIN→第一项 | 起跑/停止控制 | K4 起跑/停止，K1 返回 |
| FOC | 2 | MAIN→第二项 | FOC/速度环参数 + 测试 | K4 编辑参数，运行时显示实时转速 |
| LINE | 3 | MAIN→第三项 | 巡线参数 + 标定 | K4 编辑参数，Cal 启动标定 |
| JUNCTION | 4 | MAIN→第四项 | 路口检测阈值调试 | K4 编辑参数，显示实时路口状态 |
| GRAY | 5 | MAIN→第五项 | 灰度传感器原始值 | 实时显示16通道ADC值 |
| IMU | 6 | MAIN→第六项 | 姿态参数 + 陀螺滤波 | K4 编辑参数，显示实时欧拉角 |
| NEG | 7 | MAIN→第七项 | 负压电机参数 | K4 编辑参数，显示实时脉冲/百分比 |
| WIFI | 8 | MAIN→第八项 | WiFi 连接管理 | K4 连接/断开 |

### 2.2 通用操作

**参数编辑** (FOC/LINE/JUNCTION/IMU/NEG 页面共用)：
1. K2/K3 上下移动光标选择参数
2. K4 进入编辑模式
   - bool 类型：直接切换 0↔1
   - float 类型：显示 `*` 前缀，K2 增加步长值，K3 减小步长值
3. K1 退出编辑并保存到 Flash (`params_save_to_flash()`)
4. 参数格式化为可读字符串显示：`menu_registry_format_value()` (menu.c:477)

**额外动作** (LINE 页面专用)：
- `Cal` 项：启动灰度传感器标定
- `Clear` 项：清除标定数据

**页面切换注意事项**：
- 从 FOC 页面切换到其他页面时，`g_foc_test_run` 自动清零 (menu.c 的 `menu_wifi_ready()` 中)
- 从 RUN 页面退出时，`g_run_enable` 自动清零 (确保安全)

### 2.3 RUN 页面详情

**显示信息** (menu.c:730-869)：
- 电池电压、ADC原始值、百分比、低电/严重低电标志
- 里程计左右轮计数、计数活跃状态
- 当前路线索引

**起跑条件检测** (menu.c:790-806)：
1. `battery_monitor_is_critical()` — 电池严重低电 → 拒绝，显示 "BATTERY CRITICAL"
2. `line_follow_control_ready()` — 巡线标定未完成 → 拒绝，提示 "CAL NOT READY"
3. 1秒倒计时 → `g_run_enable = 1`
4. `neg_pressure_motor_set_percent()` — 设置负压百分比

**停止检测**：
- 手动停止：K4 按下 → `g_run_enable = 0` → 电机停机 → 保存参数 (menu.c:832-864)
- 自动停止：ISR 检测到停止条件 → `g_run_enable = 0` → 菜单检测并显示停止原因 (menu.c:815-825)

### 2.4 FOC 页面详情

**实时显示** (`menu_draw_foc_speed_runtime_status`, menu.c:523)：
- 左右轮目标/实际转速 (RPM)
- 左右轮电气角 (度)
- Vbus 总线电压 (V)

**FOC 测试模式**：
1. 在 FOC 页面设置 `g_foc_test_run = 1` + `g_foc_test_left/right_target_rpm`
2. 10kHz ISR 的 FOC 测试分支 (`isr.c:600-651`) 接管速度控制
3. 速度直接以斜坡方式达到目标值，不经过 1kHz 控制 ISR 的路线/里程逻辑
4. **警告**：测试模式下巡线被禁用 (`line_follow_update` 检测到 FOC 测试运行 → 直接返回)

### 2.5 LINE 页面详情

**实时显示** (`menu_draw_line_follow_debug_status`, menu.c:986)：
- 当前位置 (mm 坐标)
- 线位置 (-1.0 ~ 1.0, 0=中心)
- 击中通道数和16位击中位图
- 巡线状态 (FOLLOW/PRE_TURN/TURN_LEFT/TURN_RIGHT/POST_ELEMENT)
- 待执行转弯方向、丢线计数、路口锁定时间
- 偏航增量 (转弯时显示)
- 差速 RPM、最近元素触发类型
- 路线索引、停止原因

**标定操作**：
- `Cal` → `menu_lf_cal_action()` (menu.c:950) → `line_follow_calib_start()` (line_follow.c:645)
- `Clear` → `menu_lf_clear_action()` (menu.c:973) → `line_follow_calib_clear()` (line_follow.c:695)

### 2.6 JUNCTION 页面详情

**实时显示** (`menu_draw_junction_debug_status`, menu.c:1065)：
- 路口检测状态 (检测中/锁定中/空闲)
- 路口计数、确认帧数
- 前向匹配的元素列表 (route_plan_lookahead)
- 多匹配警告 (如果多个元素同时匹配同一帧)

### 2.7 GRAY 页面详情

**实时显示**：16 通道灰度 ADC 原始值，0-4095 (12位)，帮助判断：
- 传感器是否正常工作
- 赛道背景/黑线的对比度
- 是否有通道异常 (固定值/噪声过大)
- 标定时的 min/max 范围是否合理

### 2.8 IMU 页面详情

**实时显示**：Roll/Pitch/Yaw 欧拉角 (度)、陀螺各轴角速度 (度/秒)

**可调参数**：
- 陀螺低通滤波系数 `g_gyro_lp_alpha`
- Mahony 滤波器 Kp (比例增益)、Ki (积分增益)

## 3. FOC 校准与调试

### 3.1 校准流程总览

```
foc_calibrate_motor_default_cfg(&calib_cfg)   [foc_svpwm.c:697]
  → 设置默认校准参数 (对齐电压、时间、方向检测步长等)

foc_calibrate_motor(&svpwm, &loop, &enc, &pwm, &calib_cfg)  [foc_svpwm.c:725]
  ├── foc_detect_direction_local(...)   [foc_svpwm.c:538]
  │   ├── 电机对齐：注入固定 Vd 电压 (align_vd_frac)，保持 align_ms 时间
  │   ├── 开环旋转：注入 Vq 电压，按固定步长 (dirtest_step_rad) 增加角度
  │   ├── 读取编码器：跟踪机械角度变化
  │   └── 判断方向：正向旋转 → direction=+1，反向 → direction=-1
  │
  └── foc_calibrate_offset_local(...)   [foc_svpwm.c:656]
      ├── 再次对齐到电气零位 (注入 Vd)
      ├── 读取当前编码器机械角度
      └── 计算电气偏移 = 机械角 × 极对数 mod 2π
```

### 3.2 校准参数说明

| 参数 | 默认值 | 说明 | 调优建议 |
|------|--------|------|---------|
| `align_vd_frac` | ~0.3 | 对齐阶段的 Vd 占空比 | 太大会过热，太小无法对齐 |
| `align_ms` | ~2000 | 对齐持续时间 (ms) | 确保电机完全静止在对齐位置 |
| `dirtest_vq_frac` | ~0.2 | 方向检测的 Vq 占空比 | 确保电机能旋转但不失控 |
| `dirtest_settle_ms` | ~200 | 方向检测前的稳定时间 | — |
| `dirtest_ms` | ~500 | 方向检测持续时间 | 太长可能转一圈以上 |
| `dirtest_step_rad` | ~0.01 | 角度步长 (弧度) | 越小旋转越慢越平滑 |
| `dirtest_min_move_rad` | ~0.05 | 最小检测移动量 (弧度) | 小于此值认为未转动 |

### 3.3 校准失败诊断

**症状 1：校准后电机不转或抖动**
- 可能原因：方向检测失败 → `direction` 为默认值
- 检查方法：在 FOC 测试模式设置低速目标 (100RPM)，观察电机是否旋转
- 调试步骤：
  1. 切换方向符号 (交换左右电机 `direction` 参数)
  2. 检查编码器接线 (SPI 通信是否正常)
  3. 在 FOC 页面查看 `g_motor_mech_l/r_valid` — 为 0 表示编码器读取失败

**症状 2：校准后转速不稳定**
- 可能原因：电气偏移 (`elec_offset`) 不准确
- 检查方法：FOC 页面查看目标/实际转速偏差
- 调试步骤：重新校准，确保校准期间电机不受外力干扰

**症状 3：编码器读取失败 (encoder fail count 持续增加)**
- 检查 SPI 接线：SCK/MOSI/MISO/CS
- 检查 AS5047P 供电 (3.3V)
- 检查磁铁与芯片的间距 (推荐 0.5-2mm)
- 在 FOC ISR 中，编码器失败 150 个周期 (15ms) 后强制停机 (isr.c:410)

### 3.4 FOC 关键参数

| 参数 | 位置 | 说明 |
|------|------|------|
| `pole_pairs` | `foc_svpwm.h:61` | 电机极对数 (默认7) |
| `direction` | `foc_svpwm.h:62` | 方向修正 (±1) |
| `elec_offset` | `foc_svpwm.h:63` | 电气偏移 (弧度) |
| `duty_max` | `foc_svpwm.h:41` | PWM 最大占空比 |
| `vq_limit` | `foc_svpwm.h:133` | Vq 输出电压上限 |

## 4. 巡线标定与调试

### 4.1 标定流程

**启动标定**：
1. 进入 LINE 页面 (MENU_LINE_FOLLOW_DEBUG)
2. 光标移到 `Cal` 项
3. K4 执行 → `menu_lf_cal_action()` (menu.c:950) → `line_follow_calib_start()` (line_follow.c:645)

**标定过程** (`line_follow_calib_update_raw`, line_follow.c:589)：
- 每帧 (5ms) 读取 16 通道灰度值
- 更新每个通道的 min/max 值
- 累积样本计数

**标定操作**：将小车保持在赛道上，推动小车让传感器经过黑线和白底区域，使每个通道都能采集到 min(黑线) 和 max(白底) 数据。

**停止标定**：
- 再次选择 `Cal` 项 → `line_follow_calib_stop()` (line_follow.c:653)

**清除标定**：
- 选择 `Clear` 项 → `line_follow_calib_clear()` (line_follow.c:695) → 所有 min/max 重置

**标定数据查询** (WiFi 命令)：
- `line_cal_samples?` → 查询每个通道的标定样本数
- `line_cal_min?` / `line_cal_max?` → 查询每个通道的 min/max

### 4.2 标定有效性检查

`line_follow_calib_is_valid()` (line_follow.c:715)：
- 返回 true 的条件：每个通道的 `samples > 0` 或 `min < max`

`line_follow_control_ready()` (line_follow.c:576)：
- 返回 true 的条件：标定有效 + 传感器接口正常
- **影响**：未就绪时 delta=0，小车只能直行

### 4.3 评分与位置计算

**通道评分** (`line_follow_calc_channel_score`, line_follow.c:280)：
```
score = (raw - min) / (max - min)   // 归一化到 [0, 1]
score = clamp(score, 0.0, 1.0)
```

**位置估算** (`line_follow_estimate_local_peak_pos`, line_follow.c:308)：
```
position = Σ(i * score[i]) / Σ(score[i])   // 加权质心 (亚像素精度)
position = normalized to [-1.0, 1.0]
```

### 4.4 巡线参数调试

| 参数 | 说明 | 调优建议 |
|------|------|---------|
| `steer_kp` | PID 比例增益 | 增加 → 响应更快但可能振荡；减少 → 更平滑但滞后 |
| `steer_ki` | PID 积分增益 | 用于消除稳态偏差；过大可能导致积分饱和 |
| `steer_kd` | PID 微分增益 | 抑制超调；过大对噪声敏感 |
| `intersection_confirm_frames` | 路口确认帧数 | 减少 → 更快响应但可能误判；增加 → 更可靠但延迟 |
| `lost_line_timeout_s` | 丢线超时 (秒) | 过大可能冲出赛道；过小可能过早停车 |
| `turn_done_yaw_deg` | 转弯完成偏航角 | 通常 85-90° (留余量补偿惯性) |
| `pre_turn_distance_mm` | 预转弯距离 | 根据车速和转弯半径调整 |
| `turn_speed_scale` | 转弯减速比例 | 0.3-0.7，保证转弯稳定 |
| `turn_timeout_s` | 转弯超时 (秒) | 防止卡死在转弯状态 |

### 4.5 路口/元素检测调试

**元素触发配置** (`g_lf_elem_trigger_cfg[]`)：每种路线元素 (ELEM_01~ELEM_19) 可配置：
- `hit_count`：击中通道数的匹配范围
- `position`：线位置的匹配范围
- `feature_flags`：特征标志匹配 (边缘、宽线等)

**调试方法**：
1. 进入 JUNCTION 页面
2. 推动小车经过路口/元素
3. 观察显示的击中数、位置、特征标志
4. 调整对应元素的触发配置使其匹配

**多匹配警告**：当同一帧匹配多个未来元素时，LINE 页面显示 `MULTI MATCH` 警告 (line_follow.c:996-1008)

## 5. 速度控制调试

### 5.1 速度环 PI 参数

`foc_speed_loop_init_default()` (foc_svpwm.c:259) 设置默认参数，后续可通过 WiFi/菜单修改。

| 参数 | 说明 | 调优建议 |
|------|------|---------|
| `speed_pid.kp` | 速度环比例增益 | 增大 → 更快响应，过大导致振荡 |
| `speed_pid.ki` | 速度环积分增益 | 消除稳态误差，过大导致积分饱和 |
| `speed_pid.kd` | 速度环微分增益 | 通常为0 (速度环不需要微分) |
| `vq_limit` | Vq 输出电压上限 | 限制最大电流/功率 |
| `desired_omega_m` / `target_omega_m` | 目标机械角速度 | — |

### 5.2 速度估算参数

| 参数 | 说明 | 调优建议 |
|------|------|---------|
| `g_as5047p_lp_alpha` | 速度低通滤波系数 | 0.0~1.0, 越大滤波越轻(越快响应)，越小越平滑 |
| `g_as5047p_speed_avg_samples` | 速度平均样本数 | 增大 → 更平滑但滞后 |
| `g_as5047p_speed_zero_deadband_rpm` | 零速死区 (RPM) | 低于此值的转速强制为0，防止零速漂移 |

### 5.3 转速斜坡参数

| 参数 | 说明 | 调优建议 |
|------|------|---------|
| `g_base_speed_up_slope` | 基速爬升斜率 (RPM/ms) | 越大加速越快，过大导致打滑或过流 |
| `g_base_speed_down_slope` | 基速下降斜率 (RPM/ms) | 越大减速越快 |
| `g_delta_speed_up_slope` | 差速爬升斜率 (RPM/ms) | 转弯时的差速变化率 |
| `g_delta_speed_down_slope` | 差速下降斜率 (RPM/ms) | — |

这些参数在 1kHz 控制 ISR 的斜坡计算中生效 (isr.c:870-890)：
```
base_cmd_rpm += base_slope * dt   // 每1ms以固定斜率爬升
base_cmd_rpm = clamp(base_cmd_rpm, 0, base_target)  // 限幅
```

### 5.4 速度调试方法

**FOC 测试模式** (FOC 页面)：
1. 设置 `g_foc_test_run = 1`
2. 分别设置左右轮目标转速
3. 观察实际转速是否跟踪目标
4. 调整速度 PI 参数直到跟踪良好

**WiFi 实时遥测**：
- FAST 帧 (20ms) 显示目标/实际转速
- 对比 `left_target_rpm` vs `left_actual_rpm`
- 理想情况：实际转速紧密跟踪目标，无大幅超调或振荡

**转速不稳定诊断**：
- 观察 FOC 页面显示的实际 RPM 波动范围
- 如果波动 > ±10%：增大 `g_as5047p_lp_alpha` (减少滤波) 或减小 Kp
- 如果响应太慢：减小 `g_as5047p_speed_avg_samples` 或增大 Kp

## 6. WiFi 遥测调试

### 6.1 连接流程

1. 开机 → WiFi 模块上电
2. 自动连接 (如果 `WIFI_BOOT_AUTO_CONNECT_ENABLE` 开启)：
   - `wifi_uart_boot_auto_connect()` → `cpu0_main.c:121`
   - 超时时间：`WIFI_BOOT_CONNECT_TIMEOUT_MS`
3. 手动连接：进入 WIFI 页面，K4 触发连接 → `menu_wifi_connect_task()` (menu.c:335)

### 6.2 上位机使用

**PC 上位机**：`user/pc_wifi_uart_plot_qt.py`

**启动方式**：
```bash
python pc_wifi_uart_plot_qt.py
```

**功能**：
- 实时遥测数据 4 通道绘图 (Roll/Pitch/Yaw + 转速)
- 命令发送 (START/PAUSE/参数查询和设置)
- 灰度流可视化 (16通道灰度值)
- 数据保存/回放

### 6.3 遥测数据分析

**FAST 帧** (20ms 周期)：
- 姿态角 (Roll/Pitch/Yaw)：观察稳定性，异常跳变可能表示 I2C 通信问题
- Gyro Z：转弯速率，与预期转弯速率对比
- 目标/实际 RPM：速度跟踪性能

**ROUTE 帧** (50ms 周期)：
- line_pos：线位置偏移，正常巡线时应围绕 0 波动
- lost_line_cnt：丢线计数，频繁丢线表示阈值或标定问题
- route_index / lf_state / pending_turn：路线执行进度和状态机状态
- stop_reason：停止原因码，帮助定位异常停止

**POWER 帧** (100ms 周期)：
- battery_voltage_v / battery_percent：电池状态监控
- np_target_percent / np_output_pulse_us：负压电机状态

**GRAY 帧** (50ms 周期，需启用)：
- 16 通道灰度原始值：判断传感器状态和标定质量
- 启停命令：`GRAY:1` / `GRAY:0` (WiFi 文本命令)

### 6.4 命令调试

**页面切换**：`PAGE:FOC` / `PAGE:LINE` / `PAGE:RUN` 等，带 FOC 安全互锁 (切换到非 FOC 页面时自动关闭 FOC 测试模式)

**参数查询**：`<参数名>?` → 返回当前值
**参数设置**：`<参数名>:<值>` → 在线修改
**参数保存**：`SAVE` → 将所有当前参数写入 Flash

**远程起跑**：`START` → 等价于在 RUN 页面按 K4，有相同的安全检测 (电池、标定)

### 6.5 通信异常诊断

**问题：上位机无数据**
- 检查 WiFi 模块是否正常连接 (WIFI 页面查看状态)
- 检查 UART2 接线 (P10.5/P10.6)
- 检查上位机 IP 和端口配置 (`wifi_cfg.h`)

**问题：数据帧断断续续**
- CRC-8 校验失败 → 自动搜索同步字恢复 (wifi_service_process_rx_stream, line 891-921)
- 检查 UART 波特率匹配
- 检查 WiFi 信号强度

**问题：GRAY 帧不发送**
- 需要先启用：命令 `GRAY:1`

## 7. 常见故障诊断

### 7.1 开机故障

| 症状 | 可能原因 | 诊断步骤 |
|------|---------|---------|
| 屏幕显示 "INIT FAIL: IMU" | IMU660RB SPI 通信失败 | 检查 IMU 接线、供电，用示波器测 SPI 信号 |
| 屏幕不亮 | IPS200 供电/SPI 问题 | 检查背光引脚 P15.4，检查 SPI 接线 |
| 开机后卡死 | 某个初始化函数阻塞 | 逐个注释初始化函数定位问题 |
| `cpu_wait_event_ready()` 卡死 | 双核同步失败 | 检查 CPU1 是否正常启动 |

### 7.2 电机不转

| 检查项 | 方法 | 正常值 |
|--------|------|--------|
| FOC 校准成功 | 开机时观察校准过程 | 电机短暂转动后停止 |
| 编码器正常 | FOC 页面查看 encoder valid | 应为 1 |
| 运行使能 | RUN 页面 g_run_enable | 起跑后应为 1 |
| PWM 输出 | 示波器测 DRV8300 输入引脚 | 应有 10kHz PWM 波形 |
| 目标转速 | FOC 页面查看 target_rpm | 应非零 (有基速) |

### 7.3 巡线异常

| 症状 | 可能原因 | 诊断方法 |
|------|---------|---------|
| 小车找不到线 | 标定阈值不对 | GRAY 页面查看 min/max 范围，重新标定 |
| 频繁丢线 | 传感器高度变化/标定过期 | 观察 lost_line_cnt，调整阈值 |
| 转弯卡住 | 转弯超时参数不对 | LINE 页面观察 turn_yaw 和 odom |
| 路口误判 | 确认帧数太少 | JUNCTION 页面观察，增大 intersection_confirm_frames |
| 不按路线走 | 路线元素匹配失败 | JUNCTION 页面观察匹配状态，调整触发参数 |
| PID 振荡 | Kp 过大 | 减小 steer_kp，观察 line_pos 波动 |

### 7.4 IMU 姿态异常

| 症状 | 可能原因 | 诊断方法 |
|------|---------|---------|
| 姿态漂移 | 陀螺零偏未补偿 | IMU 页面观察静止时 gyro 值是否近零 |
| 姿态突变 | I2C 通信丢包 | 观察 `imu_ahrs_check_stale()` 返回 true 频率 |
| Yaw 不准 | 磁力计未融合 (本项目无磁力计) | Yaw 会随时间漂移，转弯检测用相对增量 (delta) |

### 7.5 电池/电源

| 症状 | 可能原因 | 诊断方法 |
|------|---------|---------|
| 低电误报 | ADC 分压比不对 | 用万用表实测电压对比 `battery_voltage_v` |
| 行驶中断电 | 电池内阻过大/接触不良 | 观察 POWER 帧的电压骤降 |
| 起跑被拒 | 电池严重低电 | RUN 页面显示 "BATTERY CRITICAL" |

## 8. 示波器/GPIO 性能分析

### 8.1 ISR 时间测量

**FOC ISR** (P02.6)：
- 高电平 = ISR 执行中
- 期望：< 100μs

```
示波器设置：CH1 接 P02.6，触发上升沿
测量：正脉冲宽度 = FOC ISR 执行时间
```

**如果超过 100μs**：
- 检查 SPI 通信是否超时 (编码器读取是最耗时的部分)
- 检查是否有嵌套中断打断
- 优化代码路径 (减少不必要的计算)

### 8.2 PWM 输出检查

**DRV8300 输入引脚**：
- 3 路 PWM 信号，每路 10kHz，占空比随 SVPWM 调制变化
- 死区时间由 DRV8300 硬件处理

### 8.3 SPI 通信检查

**AS5047P 编码器**：
- SCK 频率：`AS5047P_SPI_BAUD`
- 每 100μs 一次读取 → 10kHz SPI 查询率
- 示波器观察 CS 引脚下拉周期和 MISO 数据

**IMU660RB**：
- SPI 模式，5ms 读取一次 (200Hz)
- 如果数据 stale → `imu_ahrs_check_stale()` 返回 true

### 8.4 中断负载评估

用示波器测量各 ISR 的执行时间，确保总负载在可接受范围：

| ISR | 频率 | 最大允许执行时间 | 测量方法 |
|-----|------|----------------|---------|
| FOC (CPU1) | 10kHz | <80μs (留20μs余量) | P02.6 GPIO |
| 控制 (CPU0) | 1kHz | <500μs | 额外 GPIO 或软件计时 |
| 巡线 (CPU0) | 200Hz | <2ms | 额外 GPIO |
| IMU (CPU0) | 200Hz | <1ms | 额外 GPIO |

## 9. 参数Flash管理

### 9.1 参数加载

`params_load_from_flash()` → `cpu0_main.c:214`（开机时执行）

参数描述符系统 (`params_flash.h/c`) 管理所有可持久化参数。每个参数有：
- 名称字符串、类型 (float/u8/bool)、默认值、最小/最大值、步长
- 所属页面关联 (通过 `page_name` 对应到 `MENU_XXX`)
- Flash 存储地址

### 9.2 参数保存

`params_save_to_flash()`：
- 手动触发：RUN 页面停止时自动调用 (menu.c:862)、WiFi `SAVE` 命令
- 编辑触发：调试页面参数编辑退出时 (K1)
- 写入 TC264 内部 Flash 的数据扇区

### 9.3 参数查询与设置

**WiFi 命令** (wifi_service.c:1159)：
```
<参数名>?        → 查询当前值 (返回 "参数名:值")
<参数名>:<值>     → 设置新值 (在线生效)
SAVE             → 保存到 Flash
```

**菜单调试页面**：
- 使用 `menu_generic_edit_registry_task_ex()` (menu.c:578)
- 显示参数标签 + 数值 → K4 编辑 → K1 保存

### 9.4 参数出厂重置

如果参数损坏或配置混乱：
1. 清除 Flash 参数扇区 (通过编程器或代码中的擦除接口)
2. 重新开机 → `params_load_from_flash()` 检测无效数据 → 使用默认值
3. 手动调整参数后 `SAVE`
